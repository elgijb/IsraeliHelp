## Этап 1 — Создание проекта (24.11.2026)

### 1.1. Что было на компьютере в начале

| Что проверяли | Команда | Результат |

### 1.2. Настройка окружения — команды и объяснения

```bash
cat >> ~/.zshrc <<'EOF'
export JAVA_HOME="/opt/homebrew/opt/openjdk/libexec/openjdk.jdk/Contents/Home"
export PATH="$JAVA_HOME/bin:$PATH"
EOF
```
- `~/.zshrc` — файл настроек терминала zsh, он выполняется при каждом открытии нового терминала.
- `cat >> файл <<'EOF' ... EOF` — дописать текст в конец файла (не стирая старое).
- `JAVA_HOME` — переменная, по которой программы (Maven, IDE) находят Java.
- `PATH` — список папок, где терминал ищет команды. Мы добавили папку `bin` из Java в начало списка.

```bash
brew services start mysql
```
- Запускает MySQL как фоновую службу (будет запускаться и после перезагрузки Mac).
- Ответ был «already started» — служба уже работала.

```bash
mysql -u root -e "SELECT VERSION(), CURRENT_USER();"
```
- `-u root` — войти пользователем root (главный администратор MySQL).
- `-e "..."` — выполнить SQL-запрос и выйти.
- Результат: `26.10.0 root@localhost` — вход без пароля работает (так Homebrew настраивает MySQL по умолчанию).

```bash
brew install gh
```
- Устанавливает GitHub CLI — программу для работы с GitHub из терминала (создать репозиторий, войти в аккаунт).

**Интересный факт:** на компьютере есть ещё Oracle JDK 25. Когда переменная `JAVA_HOME` не задана, `mvnw` находит Java
через системную утилиту macOS и берёт JDK 25. Поэтому на проверочной странице написано `Java version 25.0.1`.
Это нормально: проект компилируется под Java 21, а работает на любой Java от 21 и новее.

### 1.3. `pom.xml` — главный файл проекта

Maven — это инструмент сборки. Он читает `pom.xml`, скачивает нужные библиотеки, компилирует Java-код
и запускает сервер.

Разбор по блокам:

```xml
<groupId>il.israelihelp</groupId>
<artifactId>israelihelp</artifactId>
<version>1.0-SNAPSHOT</version>
<packaging>war</packaging>
```
- `groupId` — «фамилия» проекта, обычно перевёрнутый домен (`israelihelp.il` → `il.israelihelp`).
- `artifactId` — имя проекта.
- `version` — версия; `SNAPSHOT` значит «в разработке».
- `packaging war` — результат сборки будет WAR (Web ARchive): архив веб-приложения для сервера.

```xml
<maven.compiler.release>21</maven.compiler.release>
<project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
```
- Компилировать код под Java 21 → проект запустится у учителя на любой Java начиная с 21.
- Исходники в UTF-8 → русские комментарии и иврит не превратятся в «кракозябры».

**Зависимости (`<dependencies>`)** — библиотеки, которые Maven скачает сам:

| Библиотека | Зачем | scope |
|---|---|---|
| `jakarta.servlet-api` 6.0.0 | классы `HttpServlet`, `HttpServletRequest`, `HttpSession` | `provided` — даёт сервер Jetty |
| `jakarta.servlet.jsp.jstl` 3.0.1 (Glassfish) | теги `<c:forEach>`, `<c:if>`, `<c:out>`, `<fmt:message>` в JSP | `provided` — уже есть внутри плагина Jetty |
| `mysql-connector-j` 26.10.0 | JDBC-драйвер: через него Java общается с MySQL | обычный (попадёт в WAR) |
| `junit-jupiter` 6.1.3 | автоматические тесты | `test` — только для тестов |

**Что значит scope:**
- без scope (compile) — библиотека нужна и для компиляции, и для работы, кладётся в WAR;
- `provided` — нужна для компиляции, но во время работы её даёт сервер;
- `test` — нужна только при запуске тестов.

**Плагины (`<build><plugins>`)**:
- `maven-compiler-plugin` — компилирует `.java` в `.class`.
- `maven-surefire-plugin` — запускает тесты (`./mvnw test`).
- `maven-war-plugin` — собирает WAR-файл.
- `jetty-ee10-maven-plugin` — веб-сервер Jetty. `ee10` означает поддержку Jakarta EE 10 (Servlet 6.0).
  - `<contextPath>/</contextPath>` — сайт открывается в корне: `http://localhost:8080/`, а не `http://localhost:8080/israelihelp/`.
  - `<port>8080</port>` — порт сервера.

### 1.4. Maven Wrapper (`mvnw`, `mvnw.cmd`, `.mvn/wrapper/maven-wrapper.properties`)

Команда: `mvn -N wrapper:wrapper`
- `-N` — «non-recursive», только для этого проекта.
- `wrapper:wrapper` — создать обёртку.

Зачем: у учителя может не быть Maven. `mvnw` (macOS/Linux) и `mvnw.cmd` (Windows) — маленькие скрипты,
которые при первом запуске сами скачают нужную версию Maven (3.10.1 — записано в `maven-wrapper.properties`).
Учителю нужно установить только Java.

### 1.5. `src/main/webapp/WEB-INF/web.xml` — настройки веб-приложения

- `WEB-INF` — особая папка: файлы внутри неё браузер **не может** открыть напрямую. Поэтому там лежат настройки и JSP.
- `<session-timeout>30</session-timeout>` — сессия пользователя заканчивается через 30 минут бездействия.
- `<http-only>true</http-only>` — cookie сессии (`JSESSIONID`) недоступна JavaScript → вредный скрипт не сможет её украсть.
- `<tracking-mode>COOKIE</tracking-mode>` — номер сессии передаётся только в cookie, а не в адресной строке (иначе его можно случайно переслать кому-то вместе со ссылкой).
- `<page-encoding>UTF-8</page-encoding>` для `*.jsp` — все JSP в UTF-8.

### 1.6. `HomeServlet.java` — первый сервлет

```java
@WebServlet("")
public class HomeServlet extends HttpServlet {
```
- **Сервлет** — Java-класс, который обрабатывает HTTP-запросы. Наследуется от `HttpServlet`.
- `@WebServlet("")` — аннотация: «этот сервлет отвечает за адрес `""`», то есть корень сайта `/`.
  Можно было бы прописать то же самое в `web.xml`, но аннотация короче и видна прямо в классе.

```java
@Override
protected void doGet(HttpServletRequest request, HttpServletResponse response)
```
- `doGet` вызывается, когда браузер делает **GET**-запрос (открыть страницу, перейти по ссылке).
- Для отправки форм позже будем использовать `doPost` (**POST**-запрос).
- `request` — всё, что прислал браузер (адрес, параметры, cookie, сессия).
- `response` — то, что мы отправим обратно.

```java
request.setAttribute("serverTime", LocalDateTime.now().format(TIME_FORMAT));
request.setAttribute("javaVersion", System.getProperty("java.version"));
request.setAttribute("serverInfo", getServletContext().getServerInfo());
```
- `setAttribute(имя, значение)` — положить данные в запрос, чтобы JSP могла их показать.
- `getServletContext()` — объект **Application** (общий для всего приложения). Здесь мы только спросили у него имя сервера; на этапе 7 будем хранить в нём общие счётчики.

```java
request.getRequestDispatcher("/WEB-INF/views/home.jsp").forward(request, response);
```
- `forward` — передать запрос JSP-странице на сервере. Браузер этого не видит: адрес в строке остаётся `/`.
- Это схема **MVC**: сервлет (Controller) готовит данные, JSP (View) их показывает.

### 1.7. `home.jsp` — проверочная страница

```jsp
<%@ page contentType="text/html;charset=UTF-8" pageEncoding="UTF-8" %>
<%@ taglib prefix="c" uri="jakarta.tags.core" %>
```
- Первая строка: страница отдаёт HTML в UTF-8.
- Вторая: подключить библиотеку тегов JSTL core под префиксом `c`.

```jsp
<c:out value="${serverTime}"/>
```
- `${serverTime}` — **EL-выражение** (Expression Language): берёт атрибут `serverTime`, который положил сервлет.
- `<c:out>` выводит значение и **экранирует** HTML-символы (`<` → `&lt;`). Это защита от XSS: если в данных окажется `<script>`, он покажется как текст, а не выполнится.

Строка `English · עברית · Русский` проверяет, что кодировка настроена правильно для всех трёх языков сайта.

открыл файл — понял, зачем пакет.

| Пакет | Роль |

### 1.11. Проблема, которую решили

**Симптом:** при запуске Jetty печатал около 1700 строк `WARNING ... scanned from multiple locations`.

**Как искали причину:**
1. Посмотрели, какие JAR-файлы упоминаются в предупреждениях.
2. Сначала оказалось, что JSTL API был в двух версиях (3.0.0 и 3.0.2) — убрали лишнюю.
3. Предупреждения остались, но теперь одна и та же библиотека `jakarta.servlet.jsp.jstl-3.0.1.jar` сканировалась дважды.
4. Пробовали настройку `containerIncludeJarPattern` — не помогло, откатили.
5. Поняли: плагин Jetty уже содержит эту библиотеку сам, а мы добавили её второй раз.

**Решение:** `<scope>provided</scope>` у JSTL в `pom.xml`. Результат: 0 предупреждений.

### 1.13. Вопросы, которые могут задать на защите

- **Что такое сервлет?** Java-класс, который обрабатывает HTTP-запросы на сервере (методы `doGet`, `doPost`).
- **Чем GET отличается от POST?** GET — получить данные, параметры видны в адресе; POST — отправить данные (форма), параметры в теле запроса.
- **Зачем JSP лежат в WEB-INF?** Чтобы их нельзя было открыть напрямую, минуя сервлет (и его проверки).
- **Что такое forward?** Передача запроса от сервлета к JSP на сервере, без нового запроса от браузера.
- **Зачем Maven Wrapper?** Чтобы проект запускался там, где не установлен Maven.
- **Что такое scope provided?** Библиотека нужна для компиляции, но во время работы её предоставляет сервер.
- **Почему пароль от базы не в Git?** Репозиторий публичный — пароль увидят все. Храним только пример файла.

## Этап 2 — База данных (24.11.2026)

### 2.1. Схема: какие таблицы и как они связаны

```
users (1) ──< applications >── (1) events
```
- Один пользователь может подать много заявок; на одно мероприятие может быть много заявок.
- Таблица `applications` — **связующая таблица** для связи «многие ко многим» между `users` и `events`.

### 2.2. `database/schema.sql` — разбор

```sql
DROP DATABASE IF EXISTS IsraeliHelp;
CREATE DATABASE IsraeliHelp CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
USE IsraeliHelp;
```
- Удалить старую базу (если есть) и создать заново → скрипт можно запускать много раз, результат всегда одинаковый.
- `utf8mb4` — настоящий полный UTF-8 в MySQL (обычный `utf8` в MySQL неполный). Нужен для иврита, русского, любых символов.
- `COLLATE utf8mb4_unicode_ci` — правила сравнения строк; `ci` = case-insensitive (поиск «haifa» найдёт «Haifa»).
- `USE` — дальше все команды выполняются в этой базе.

**Таблица `users`**

| Колонка | Тип | Почему так |
|---|---|---|
| `id` | `INT UNSIGNED AUTO_INCREMENT` | номер строки, MySQL сам увеличивает: 1, 2, 3…; `UNSIGNED` — без отрицательных |
| `username` | `VARCHAR(50) NOT NULL` + `UNIQUE` | строка до 50 символов, обязательная, не может повторяться |
| `email` | `VARCHAR(255) NOT NULL` + `UNIQUE` | 255 — максимальная разумная длина e-mail |
| `password_hash` | `VARCHAR(255) NOT NULL` | хеш пароля (около 100 символов), не сам пароль |
| `role` | `ENUM('USER','ADMIN') DEFAULT 'USER'` | только одно из двух значений; новый пользователь — USER |
| `created_at` | `TIMESTAMP DEFAULT CURRENT_TIMESTAMP` | MySQL сам ставит текущее время при INSERT |

- `PRIMARY KEY (id)` — **первичный ключ**: уникально определяет строку.
- `CONSTRAINT uq_users_username UNIQUE (username)` — **ограничение** с именем. Имя полезно: в тексте ошибки видно, какое правило нарушено.

**Таблица `events`**
- `description TEXT` — длинный текст (до 65 535 байт), в отличие от `VARCHAR` с лимитом.
- `category VARCHAR(30)`, `city VARCHAR(30)` — храним **коды** (`FOOD`, `TEL_AVIV`), а не названия. Почему: сайт на трёх языках, и название «Тель-Авив / תל אביב / Tel Aviv» будет браться из файла перевода по коду. Список разрешённых кодов будет проверяться в Java (enum).
- `event_date DATETIME` — дата и время мероприятия (без часового пояса — всё по времени Израиля).
- `required_volunteers SMALLINT UNSIGNED` — небольшое целое 0…65 535.
- `CONSTRAINT chk_events_volunteers CHECK (required_volunteers BETWEEN 1 AND 500)` — база сама не даст сохранить 0 или 1000. Это **третья линия защиты** после JS и Java.
- `status ENUM('OPEN','FULL','CANCELLED','COMPLETED')` — открыто / мест нет / отменено / прошло.
- `image VARCHAR(100) NULL` — имя файла картинки; `NULL` = картинки может не быть.
- `INDEX idx_events_city (city)` — **индекс**: как оглавление в книге, ускоряет `WHERE city = ?`. Сделаны для полей, по которым фильтрует каталог.

**Таблица `applications`**
- `CONSTRAINT uq_applications_user_event UNIQUE (user_id, event_id)` — **составной уникальный ключ**: пара (пользователь, мероприятие) не может повториться. Это требование ТЗ «запретить повторную запись» на уровне базы.
- `FOREIGN KEY (user_id) REFERENCES users (id)` — **внешний ключ**: в `user_id` можно записать только `id`, который существует в `users`.
- `ON DELETE CASCADE` — если удалить мероприятие, его заявки удалятся автоматически (иначе база не дала бы удалить мероприятие, у которого есть заявки).
- `ENGINE = InnoDB` — движок таблиц MySQL, который поддерживает внешние ключи и транзакции.

### 2.3. `database/sample_data.sql` — тестовые данные

- Явно указываем `id` (1, 2, 3…), чтобы заявки могли ссылаться на конкретных пользователей и мероприятия.
- E-mail на домене `example.com` — он официально зарезервирован для примеров; реальных людей там нет (требование ТЗ про личные данные).
- Тексты мероприятий на английском (язык сайта по умолчанию).
- Разные статусы, чтобы было что показать: 9 OPEN, 1 FULL (Holon — нужно 2, одобрено 2), 1 CANCELLED (Eilat), 1 COMPLETED (прошедшее, Tel Aviv).
- Даты — декабрь 2026 … март 2027 (будущие), одно — октябрь 2026 (прошедшее).

**Откуда хеши паролей.** Сначала написан класс `PasswordHasher`, потом команда:
```bash
java -cp target/classes il.israelihelp.service.PasswordHasher 'Demo123!'
```
- `-cp target/classes` — где искать скомпилированные классы.
- Дальше — полное имя класса с методом `main` и аргумент (пароль в кавычках, потому что `!` особый символ в терминале).
- Для трёх пользователей с паролем `Demo123!` команда запускалась три раза — и хеши получились **разные**, потому что каждый раз новая случайная соль.

### 2.4. `PasswordHasher.java` — как хранятся пароли

Формат строки в базе: `pbkdf2$210000$<соль>$<хеш>`

- **Хеш** — односторонняя функция: из пароля легко получить хеш, а из хеша пароль — нельзя.
- **Соль** — 16 случайных байт для каждого пароля. Без соли одинаковые пароли давали бы одинаковые хеши, и по готовым таблицам можно было бы угадать популярные пароли.
- **210 000 итераций** — хеш считается многократно, чтобы перебор паролей был очень медленным (рекомендация OWASP для PBKDF2-SHA256).
- `SecureRandom` — генератор случайных чисел для криптографии (обычный `Random` предсказуем).
- `MessageDigest.isEqual` — сравнение за одинаковое время (обычное сравнение останавливается на первом различии, и по времени можно что-то узнать).
- `spec.clearPassword()` — стереть пароль из памяти после использования.
- `verify(...)` возвращает `false` на любой неправильный формат — не падает с ошибкой.

**Почему класс написан на этапе 2, а не 7:** без него нельзя было получить настоящие хеши для тестовых пользователей. Регистрация и вход (которые его используют) — всё равно этап 7.

### 2.5. `PasswordHasherTest.java` — первые автотесты

- `@Test` — метод является тестом. JUnit запускает все такие методы командой `./mvnw test`.
- `assertTrue(условие)` / `assertFalse(...)` / `assertNotEquals(a, b)` — проверки; если не выполнились, тест красный.
- 6 тестов: правильный пароль подходит; неправильный нет (и регистр важен); одинаковые пароли → разные хеши; хеш не содержит пароль; пароль на иврите/русском работает; испорченная строка из базы не ломает программу.
- Результат: `Tests run: 6, Failures: 0, Errors: 0`.

### 2.6. `database/create_user.sql` — отдельный пользователь MySQL

```sql
CREATE USER IF NOT EXISTS 'israelihelp'@'localhost' IDENTIFIED BY 'change_me';
GRANT SELECT, INSERT, UPDATE, DELETE ON IsraeliHelp.* TO 'israelihelp'@'localhost';
```
- **Принцип минимальных прав**: сайту нужны только 4 CRUD-операции. Если кто-то найдёт ошибку в сайте, он не сможет удалить таблицы (`DROP`) или зайти в другие базы.
- `'localhost'` — подключаться можно только с этого же компьютера.
- В Git лежит `change_me`, а настоящий пароль я подставил при выполнении:
  ```bash
  PW=$(openssl rand -hex 12)                                   # случайные 24 символа
  sed "s/change_me/$PW/" database/create_user.sql | mysql -u root
  ```
  `sed` заменяет текст, `|` передаёт результат в `mysql`. Пароль записан только в `src/main/resources/db.properties` (он в `.gitignore` — проверено командой `git check-ignore`).

### 2.9. Проблема, которую нашли при проверке README

В README сначала была команда `mysql -u root -p -e "source database/schema.sql"`. Я выполнил её так, как сделал бы учитель, — ошибка `1064`: в MySQL 26.10 команда `source` через `-e` не работает.
Заменил на перенаправление `mysql -u root -p < database/schema.sql` (`<` = «подать файл на вход программе»). В PowerShell `<` не работает, поэтому для Windows добавлен вариант `cmd /c "..."` (выполнить команду через классическую командную строку).

### 2.10. Вопросы на защите

- **Что такое первичный ключ?** Колонка, которая уникально определяет строку (`id`).
- **Что такое внешний ключ?** Колонка, значение которой обязано существовать в другой таблице (`applications.user_id` → `users.id`).
- **Как запрещена повторная запись?** `UNIQUE (user_id, event_id)` в базе + проверка в Java (этап 7).
- **Что будет при удалении мероприятия с заявками?** Заявки удалятся автоматически — `ON DELETE CASCADE`.
- **Почему пароли не хранятся открыто?** При утечке базы злоумышленник получит только хеши; из хеша пароль не восстановить, а перебор очень медленный из-за 210 000 итераций.
- **Зачем соль?** Чтобы одинаковые пароли имели разные хеши.
- **Почему сайт подключается не как root?** Принцип минимальных прав.
- **Почему город хранится как код?** Сайт трёхъязычный: по коду берётся название на нужном языке.
- **Где гарантия, что данные сохранятся после перезапуска?** MySQL хранит данные на диске (InnoDB); проверено перезапуском службы.
